## ВВЕДЕНИЕ

В рамках преддипломной практики была поставлена задача разработки системы AI-визуализации применения товара на объекте покупателя по фотографии и текстовому запросу. Предметной областью выбран автомобильный тюнинг: пользователь загружает фотографию автомобиля, описывает желаемое изменение на естественном языке, а система самостоятельно находит деталь в каталоге, выделяет нужную область на фото и генерирует фотореалистичный результат.

Для успешного выполнения поставленной задачи необходимо было применить знания в сфере разработки микросервисных приложений, машинного обучения, а также изучить современные модели компьютерного зрения и генерации изображений.

В разработанной системе пользователь загружает одно или несколько фото автомобиля, вводит запрос на естественном языке (например, «поставь карбоновый спойлер» или «смени диски»), после чего LLM-агент автоматически выполняет поиск детали в каталоге, сегментацию целевой области и генерацию фотореалистичного изображения.

Для выполнения поставленной задачи необходимо было реализовать следующий функционал:

- семантический поиск товара в каталоге по текстовому запросу;
- автоматическая сегментация области на фотографии без ручной разметки;
- генерация фотореалистичного изображения с применённой деталью;
- агентная оркестрация пайплайна обработки на базе LLM;
- стриминг событий агента в реальном времени через SSE;
- управление каталогом деталей с фоновой обработкой изображений.


## 1 Сравнительный анализ существующих систем визуализации товаров в e-commerce

### 1.1 Сервис Zalando Virtual Try-On

Zalando — крупнейший европейский онлайн-ритейлер одежды. В 2024 году компания запустила пилот 3D-примерочной: пользователь указывает рост, вес и параметры фигуры, после чего система генерирует персонализированный аватар и отображает одежду с учётом посадки и складок ткани [1]. В апреле 2025 года Zalando приобрёл стартап DeepAR — крупнейшего европейского поставщика AR-примерки — для формирования собственного каталога цифровых двойников одежды. Система работает только с брендами, предоставившими 3D-модели своих изделий; произвольный каталог не поддерживается.

Ограничением данного подхода является необходимость подготовки профессиональных 3D-моделей для каждой единицы товара, а также привязка исключительно к категории одежды. Пользователь не может загрузить собственную фотографию и увидеть результат в произвольном контексте.

### 1.2 Приложение IKEA Place

IKEA Place — AR-приложение на базе Apple ARKit и Google ARCore, позволяющее разместить мебель в реальном интерьере через камеру смартфона [2]. Система строит 3D-карту помещения в реальном времени и накладывает модель мебели с соблюдением масштаба и освещения.

Приложение демонстрирует высокое качество визуализации для подготовленных 3D-моделей, однако ограничено каталогом IKEA. Для каждой единицы товара требуется профессионально подготовленная 3D-модель, что делает решение неприменимым для длинного хвоста каталога. Текстовые запросы на естественном языке не поддерживаются — пользователь вручную выбирает товар из каталога.

### 1.3 Amazon Virtual Try-On

Amazon Virtual Try-On — инструмент примерки одежды, запущенный в 2023 году [3]. Пользователь загружает собственное фото, система с помощью диффузионных моделей накладывает выбранную вещь с адаптацией к позе и фигуре. По данным Amazon, внедрение инструмента снизило возвраты в категории одежды на 15–25% среди пользователей, воспользовавшихся примеркой.

Amazon Virtual Try-On наиболее близок к подходу, реализованному в данной работе, поскольку также использует генеративные модели для визуализации. Принципиальное ограничение — система заточена исключительно под одежду и не применима к другим категориям. Пользователь самостоятельно выбирает конкретный товар, а не описывает желаемое изменение на естественном языке.

Общими ограничениями всех рассмотренных систем являются: заточенность под конкретные категории товаров; необходимость специально подготовленных 3D-моделей или размеченных датасетов; отсутствие поддержки произвольного пользовательского запроса на естественном языке; отсутствие сквозной автоматизации — пользователь самостоятельно выбирает товар и область применения.


## 2 Обзор технологий разработки

### 2.1 Фреймворк FastAPI

FastAPI — высокопроизводительный фреймворк для создания REST API на языке Python, разработанный Себастьяном Рамиресом в 2018 году [4]. Фреймворк построен поверх Starlette (ASGI-сервер) и Pydantic (валидация данных) и является одним из наиболее быстрых Python-фреймворков, уступая только чистому Starlette и Uvicorn.

Основными преимуществами FastAPI являются нативная поддержка асинхронного программирования через async/await, автоматическая генерация документации OpenAPI (Swagger UI), валидация входных данных на уровне типов Python и высокая производительность. FastAPI поддерживает внедрение зависимостей, что упрощает управление жизненным циклом объектов, таких как соединения с базой данных и сессии ML-моделей.

В контексте данного проекта асинхронная природа FastAPI критически важна: ML-операции (сегментация, генерация изображений) занимают от нескольких секунд до нескольких минут. Асинхронная обработка позволяет серверу принимать новые запросы во время выполнения тяжёлых вычислений в фоновом потоке, не блокируя event loop. Для этого синхронные вызовы ML-моделей оборачиваются в `loop.run_in_executor`, что перемещает вычисления в отдельный поток.

FastAPI используется в проекте для реализации обоих микросервисов: `core_service` (управление сессиями агента, SSE-стриминг) и `accessories_processing` (управление каталогом деталей, семантический поиск).

### 2.2 Агентный фреймворк LangChain

LangChain — фреймворк для разработки приложений на базе языковых моделей, предоставляющий абстракции для построения цепочек вызовов, агентов и инструментов [5]. В данной работе используется LangChain для реализации ReAct-агента — архитектуры, в которой языковая модель чередует шаги рассуждения (Reasoning) и действия (Acting), вызывая внешние инструменты по мере необходимости.

Агент ReAct на каждом шаге формулирует мысль (что нужно сделать далее), выбирает инструмент из доступного набора, вызывает его с определёнными параметрами, анализирует результат и принимает решение о следующем действии. Цикл продолжается до тех пор, пока агент не получит достаточно информации для формирования финального ответа [6].

LangChain предоставляет декоратор `@tool` для определения инструментов, класс `create_react_agent` для создания агента и интеграции с различными провайдерами языковых моделей (OpenAI, Anthropic, локальные модели через OpenAI-совместимый интерфейс). В проекте определены три инструмента: `search_parts` (поиск детали в каталоге), `segment_object` (сегментация области на фото) и `generate_image` (генерация результата инпейнтинга).

### 2.3 Модели сегментации SAM 2 и GroundingDINO

Для автоматического выделения области применения детали на фотографии в проекте используется связка двух моделей: GroundingDINO и SAM 2.

GroundingDINO (IDEA Research, 2024) — детектор объектов с открытым словарём, способный локализовать произвольный объект по текстовому описанию без предобучения на специализированных датасетах [7]. Модель строится на базе DINO-детектора с добавлением модулей слияния текстовых и визуальных признаков. На вход принимает изображение и текстовый запрос, на выходе возвращает координаты ограничивающих рамок обнаруженных объектов.

SAM 2 (Meta AI, 2024) — универсальная модель сегментации, способная по подсказке (точка, рамка или частичная маска) построить точную бинарную маску объекта [8]. Архитектура включает ViT-энкодер изображения, энкодер подсказок и декодер маски на основе трансформера. SAM 2 работает в 6 раз быстрее предшественника SAM 1 при более высоком качестве.

В проекте GroundingDINO локализует объект по текстовому запросу пользователя и возвращает bounding box, SAM 2 строит точную маску по полученному bounding box. Такая связка позволяет сегментировать произвольные объекты без дообучения — достаточно текстового описания.

### 2.4 Диффузионная модель FLUX

Диффузионные модели — класс генеративных моделей, основанных на двух процессах: прямая диффузия (постепенное добавление гауссовского шума к изображению) и обратная диффузия (обученная нейросеть итеративно восстанавливает изображение из шума). Для задачи инпейнтинга шум добавляется только в замаскированную область, а остальные пиксели фиксируются [9].

FLUX (Black Forest Labs) использует архитектуру Multimodal Diffusion Transformer (MMDiT) вместо традиционной U-Net [10]. Трансформерные блоки с механизмом двунаправленного внимания между текстовыми токенами и патчами изображения позволяют каждому патчу «видеть» все остальные патчи и все токены промпта одновременно, что улучшает семантическое понимание и глобальную когерентность генерации.

В проекте в качестве основной модели используется FLUX.2 Pro — модель следующего поколения с нативной поддержкой массива входных изображений. Это позволяет передать модели одновременно маску, референсное изображение детали и фотографию автомобиля, благодаря чему модель самостоятельно интерпретирует роли входных данных на основе промпта.


## 3 Обзор реализованного проекта

### 3.1 Постановка задачи

В рамках дипломной работы ставится задача разработки системы AI-визуализации применения товара на объекте покупателя. Функции, которые необходимо реализовать:

- приём фотографии автомобиля и текстового запроса на естественном языке;
- автоматический поиск подходящей детали в каталоге по семантическому сходству;
- автоматическая сегментация области применения на фотографии;
- генерация нескольких вариантов фотореалистичного изображения с применённой деталью;
- отображение хода выполнения агента в реальном времени;
- управление каталогом деталей с автоматической обработкой загруженных изображений.

### 3.2 Описание архитектуры и реализации проекта

Система построена по микросервисной архитектуре и состоит из трёх основных компонентов: клиентское приложение (SvelteKit), основной сервис `core_service` (FastAPI) и сервис каталога `accessories_processing` (FastAPI). Для передачи задач фоновым воркерам используется Redis в связке с библиотекой SAQ. Данные хранятся в PostgreSQL с расширением pgvector для векторного поиска. Все компоненты упакованы в Docker-контейнеры и описаны в `docker-compose.yml`.

#### 3.2.1 Структура проекта

Проект организован в виде монорепозитория с тремя основными директориями:

- `core_service/` — основной бэкенд-сервис с агентом и API сессий;
- `accessories_processing/` — сервис каталога деталей с ML-обработкой;
- `frontend/` — клиентское приложение на SvelteKit.

Каждый сервис имеет собственный `Dockerfile` с многоэтапной сборкой. ML-модели загружаются при первом запуске и кешируются в именованном Docker-томе.

#### 3.2.2 Сервис каталога деталей

Сервис `accessories_processing` отвечает за управление каталогом тюнинговых деталей. При загрузке новой детали через `POST /api/parts/upload` API сохраняет исходное изображение, создаёт запись в базе данных и ставит фоновую задачу в очередь. Воркер выполняет обработку в три шага: удаление фона с изображения детали моделью U²-Net через библиотеку rembg, вычисление 384-мерного векторного эмбеддинга текстового описания моделью `all-MiniLM-L6-v2`, обновление статуса детали на `ready`.

Семантический поиск реализован через вычисление косинусного сходства между вектором запроса и эмбеддингами деталей в каталоге. Результаты с оценкой ниже порога 0,4 отсекаются. Формула косинусного сходства (1):

$$\text{sim}(q, v) = \frac{q \cdot v}{\|q\| \cdot \|v\|}$$                                    (1)

Где q — вектор запроса, v — вектор описания детали.

#### 3.2.3 Сегментационный пайплайн

Сегментация реализована в `core_service/app/models/segmentation.py`. GroundingDINO принимает изображение, нормализованное до размера 800×800, и текстовый запрос. Модель возвращает координаты ограничивающих рамок обнаруженных объектов в нормализованном формате, которые конвертируются в абсолютные пиксельные координаты. SAM 2 строит бинарную маску для каждой рамки. Итоговая маска формируется как поэлементный максимум всех частных масок, что обеспечивает обработку множественных вхождений одного объекта (например, всех видимых колёс).

Обе модели инициализируются как ленивые синглтоны и предзагружаются при старте воркера в строго определённом порядке для избежания конфликтов контекстов PyTorch.

#### 3.2.4 Агент и оркестрация

Агентная система является центральным компонентом `core_service`. LangChain ReAct-агент получает системный промпт с инструкциями и набор из трёх инструментов: `search_parts`, `segment_object`, `generate_image`. На каждом шаге языковая модель решает, какой инструмент вызвать, формирует параметры вызова, получает результат и принимает решение о следующем действии.

Типичная сессия содержит 8 событий: мысль агента → вызов поиска → результат поиска → вызов сегментации → результат сегментации → вызов генерации → результат генерации → финальный ответ.

Каждое событие сохраняется в поле `events` записи `AgentSession` в формате JSONB. SSE-эндпоинт опрашивает базу данных с интервалом 0,5 секунды и отправляет клиенту только новые события.

Архитектура поддерживает три провайдера языковых моделей (OpenAI, Anthropic, локальные модели через OpenAI-совместимый интерфейс) и семь провайдеров генерации изображений, переключаемых через переменные окружения или параметры запроса.

#### 3.2.5 Клиентское приложение

Клиентское приложение построено на SvelteKit и состоит из двух страниц: Studio (загрузка фото и запуска агента) и Parts (каталог деталей). Страница Studio поддерживает загрузку нескольких фотографий автомобиля через диалог выбора файла или drag-and-drop. После отправки запроса приложение подключается к SSE-стриму и отображает журнал выполнения агента в реальном времени с цветовой дифференциацией по типу события.

## ЗАКЛЮЧЕНИЕ

В ходе выполнения преддипломной практики была разработана система AI-визуализации применения товаров на объекте покупателя по фотографии и текстовому запросу, реализованная на примере автомобильного тюнинга. Система включает микросервисную архитектуру из двух бэкенд-сервисов и клиентского приложения, каталог деталей с семантическим поиском на основе векторных эмбеддингов, пайплайн сегментации на базе SAM 2 и GroundingDINO, генерацию изображений через диффузионные модели и LLM-агент для автоматической оркестрации обработки.

В ходе работы были применены знания, полученные в результате обучения в Кубанском Государственном Университете. Основными из них являются навыки разработки клиент-серверных приложений, работа с языками Python и JavaScript, знание методов машинного обучения и компьютерного зрения.

Благодаря наставлениям куратора был приобретён опыт проектирования микросервисных систем с ML-компонентами, работы с диффузионными моделями генерации изображений, а также построения агентных систем на базе LLM.
